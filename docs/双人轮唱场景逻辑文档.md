# 双人轮唱场景逻辑文档

> 本文档描述基于 ZegoExpressEngine SDK 的双人轮唱场景完整业务逻辑
> 最后更新：2026-03-10

## 一、整体架构

### 1.1 角色定义

| 角色 | 定义 | 推流状态 | 拉流策略 |
|------|------|----------|----------|
| **主播** | 正在推流的用户 | `isPublishing = true` | 只拉辅路流 (`_aux_`，纯人声) |
| **观众** | 未推流的用户 | `isPublishing = false` | 只拉主路流 (`_main_`，人声+伴奏) |

### 1.2 队伍定义

- **TeamA**：房间内的第一支队伍
- **TeamB**：房间内的第二支队伍
- 每支队伍推两路流：主路 + 辅路

### 1.3 核心状态变量

| 变量名 | 类型 | 说明 |
|--------|------|------|
| `isPublishing` | Bool | 是否正在推流 |
| `isMutedByCompetition` | Bool | 是否因竞争失败被静音 |
| `localPickSongTimestamp` | UInt64 | 本地点歌时间戳 |
| `effectiveSong` | SongItem? | 当前生效的歌曲 |
| `myTeam` | ChorusTeam? | 我的队伍（TeamA/TeamB） |
| `seiSyncManager.isSinging` | Bool | 是否正在唱歌（用于SEI） |
| `seiSyncManager.switchTimeStamp` | UInt64 | 切换时间点 |
| `seiSyncManager.hasSwitched` | Bool | 切换是否已执行 |

## 二、推流逻辑

### 2.1 上麦条件

```
上麦允许条件：房间内队伍数量 < 2

具体规则：
1. 房间内没有流 → 可以推流，作为 TeamA
2. 房间内有合法流（有队伍标记），且只有一队 → 可以推流，作为另一队
3. 房间内有合法流，且有两队 → 不可以推流，提示"房间已满"
```

### 2.2 单队上麦限制

当房间内只有一队时，另一队点击上麦需要判断：

```
if effectiveSong != nil:
    提示"当前歌曲演唱完才能上麦"
    禁止上麦
else:
    允许正常上麦
```

### 2.3 推流实现

1. **推两路流**：
   - 主路：`chorus_{roomID}_{team}_main_{uuid}`
   - 辅路：`chorus_{roomID}_{team}_aux_{uuid}`

2. **设置流额外信息**：
   - 主路和辅路都需要设置 `extraInfo = "team:A"` 或 `"team:B"`

3. **流对齐配置**：
   - 主路和辅路都开启 `setStreamAlignmentProperty`
   - 配置 `forceSynchronousNetworkTime = 1`

### 2.4 停止推流

停止推流时执行：
- 停止推流（主路+辅路）
- 停止播放器
- 重置 SEI 管理器
- 清空歌曲信息
- 重置竞争静音状态
- 隐藏队伍头像
- 更新播放控制按钮可见性（隐藏）

---

## 三、拉流逻辑

### 3.1 角色区分拉流

| 角色 | 拉流标记 | 流内容 |
|------|----------|--------|
| 主播（正在推流） | `_aux_` | 纯人声 |
| 观众（未推流） | `_main_` | 人声+伴奏 |

### 3.2 流更新处理

**新增流** (`onRoomStreamUpdate: .add`):
1. 检查流是否包含合法队伍信息（extraInfo 包含 team:A/B）
2. 将流加入 `roomStreamList`
3. 根据当前角色判断是否拉取此流（`shouldPlayStream`）
4. 显示对应队伍头像

**删除流** (`onRoomStreamUpdate: .delete`):
1. 根据 streamID 从 `roomStreamList` 中删除（避免 OC 对象匹配问题）
2. 停止拉流
3. 隐藏对应队伍头像

### 3.3 拉流对齐

- 全局设置 `setPlayStreamsAlignmentProperty(.try)`
- 与推流端的 `setStreamAlignmentProperty` 成对使用

## 四、点歌逻辑

### 4.1 本地点歌流程

```
1. 记录点歌时间戳 localPickSongTimestamp
2. 设置当前歌曲 currentSong / effectiveSong
3. 更新 SEI 管理器（歌曲 + 时间戳）
4. 重置竞争静音状态 isMutedByCompetition = false
5. 加载歌曲
   ├─ 成功：
   │   ├─ 生成切换时间戳（总时长/2 ± 10s随机偏移）
   │   └─ 如果已在推流状态，自动开始播放
   └─ 失败：打印错误
```

### 4.2 从 SEI 同步歌曲（主播之间）

当主播收到其他主播的 SEI 且满足：
- `isSinging = true`
- 歌曲名称与本地不同
- 歌曲名称非空

**执行动作**：
```
1. 本地静默加载歌曲
2. 本地音量设为 0（静音播放，仅用于同步进度）
3. 推流音量设为 60（SDK默认值，让别人能听到）
4. seek 到对方当前进度
5. 开始播放
```

### 4.3 观众同步

观众收到 SEI 时：
- **仅更新 UI 显示**（歌曲名、进度条）
- **不加载、不播放**本地音频

## 五、SEI 处理逻辑

### 5.1 SEI 数据结构

```swift
struct ChorusSEIData {
    totalDuration: UInt64      // 总时长（毫秒）
    currentProgress: UInt64    // 当前进度（毫秒）
    isSinging: Bool            // 是否正在唱歌
    switchTimeStamp: UInt64    // 切换时间点（毫秒）
    currentTeam: String        // 当前队伍 "A" / "B"
    currentSong: String        // 当前歌曲名称
    pickSongTimestamp: UInt64  // 点歌时间戳（毫秒）
}
```

### 5.2 SEI 发送规则

- 仅推流用户发送 SEI
- 发送间隔限制：100ms
- 播放状态变化时立即发送（强制发送）
- 进度回调时发送（受间隔限制）

### 5.3 推流用户收到 SEI

```
1. 播放结束判断？
   └─ 条件：totalDuration > 0 && currentProgress >= totalDuration
   └─ 是：清空播放信息，返回

2. 对方 isSinging && 歌曲不同 && 歌曲名非空？
   └─ 是：同步歌曲（静默播放：音量0 + 推流音量60）

3. 双方都点了歌 && 对方时间戳更早 && 歌曲不同？
   └─ 是：竞争失败，执行 handleLostSongCompetition

4. 对方 isSinging && 有切换时间戳 && 本地无切换时间戳？
   └─ 是：同步切换时间戳

5. 歌曲一致？
   └─ 是：进度对齐（差>100ms则seek）
```

### 5.4 观众收到 SEI

```
1. 播放结束判断？
   └─ 是：清空播放信息，返回

2. isSinging == false？
   └─ 是：忽略（不处理）

3. 同步歌曲信息（仅更新UI）
4. 同步进度显示（仅更新UI）
5. 同步切换时间戳（如果有）
```

### 5.5 播放结束处理

**判断条件**：`currentProgress >= totalDuration`

**执行动作**：
```swift
clearPlaybackInfo() {
    effectiveSong = nil
    currentSong = nil
    localPickSongTimestamp = 0
    seiSyncManager.reset()
    accompanimentPlayer.stop()
    chorusView.playerControlView.resetUI()
}
```

## 六、点歌竞争逻辑（仅主播）

### 6.1 竞争条件

```
双方都有点歌时间戳（> 0）且 对方时间戳 < 本地时间戳 且 歌曲不同
```

### 6.2 竞争失败处理

```swift
handleLostSongCompetition() {
    // 1. 推流静音（主路+辅路）
    mutePublishStreamAudio(true)
    mutePublishStreamAudio(true, .aux)
    isMutedByCompetition = true

    // 2. 本地播放器音量设为 0
    accompanimentPlayer.setLocalVolume(0)

    // 3. 标记不在唱歌
    seiSyncManager.setIsSinging(false)

    // 4. 更新播放控制按钮可见性（隐藏）
    updatePlayerControlVisibility()
}
```

### 6.3 竞争成功（或没有竞争）

- 正常播放
- 本地音量 60（SDK默认值）
- 推流不静音
- isSinging = true

## 七、队伍切换逻辑

### 7.1 触发条件

```
前提：房间内有两队都在推流
条件：当前进度 >= 切换时间戳 && 未切换过
执行者：正在推流的主播
```

**注意**：仅一队时不执行切换逻辑

### 7.2 切换动作（双方本地执行）

假设从 TeamA 切换到 TeamB：

| 状态 | TeamA（演唱者→等待者） | TeamB（等待者→演唱者） |
|------|------------------------|------------------------|
| isSinging | `true` → `false` | `false` → `true` |
| mutePublish | `false` → `true` | `true` → `false` |
| 本地音量 | `60` → `0` | `0` → `60` |

### 7.3 代码实现

```swift
performTeamSwitch() {
    // 1. 切换 isSinging 状态
    seiSyncManager.toggleSingingState()
    let newIsSinging = seiSyncManager.isSinging

    // 2. 重置竞争静音状态
    if isMutedByCompetition && newIsSinging {
        isMutedByCompetition = false
    }

    // 3. 更新推流 mute 状态
    zego.mutePublishStreamAudio(!newIsSinging)
    zego.mutePublishStreamAudio(!newIsSinging, channel: .aux)

    // 4. 调整本地播放器音量
    accompanimentPlayer.setLocalVolume(newIsSinging ? 60 : 0)

    // 5. 更新播放控制按钮可见性
    updatePlayerControlVisibility()

    // 6. 标记已切换
    seiSyncManager.markAsSwitched()
}
```

## 八、播放控制按钮显示逻辑

### 8.1 按钮组成

仅保留 **停止按钮**，移除播放/暂停按钮。

### 8.2 显示规则

```swift
updatePlayerControlVisibility() {
    let shouldShowControls = isPublishing && seiSyncManager.isSinging
    playerControlView.setControlsHidden(!shouldShowControls)
}
```

**显示条件**：必须同时满足
1. `isPublishing == true`（正在推流）
2. `seiSyncManager.isSinging == true`（正在演唱）

### 8.3 状态变更触发点

| 场景 | 操作 |
|------|------|
| 上麦成功 | 调用 `updatePlayerControlVisibility()` |
| 下麦成功 | 调用 `updatePlayerControlVisibility()`（隐藏）|
| 播放开始 | 调用 `updatePlayerControlVisibility()` |
| 播放暂停/停止/结束 | 调用 `updatePlayerControlVisibility()`（隐藏）|
| 竞争失败 | 调用 `updatePlayerControlVisibility()`（隐藏）|
| 队伍切换 | 调用 `updatePlayerControlVisibility()` |

## 九、音量控制汇总

### 9.1 主播音量状态

| 场景 | 本地音量 | 推流音量 | mutePublish |
|------|----------|----------|-------------|
| 正常演唱 | 60 | 60 | false |
| 竞争失败 | 0 | 60 | true |
| 等待切换（非演唱方） | 0 | 60 | true |

### 9.2 观众音量状态

观众不播放本地音频，仅通过拉流听到声音。

## 十、状态流转图

```
[点歌阶段]
主播A点歌 ───────────────────────────► 主播B收到SEI
  │                                        │
  │ 1. 记录时间戳                          │ 1. 判断isSinging=true
  │ 2. 加载歌曲                            │ 2. 歌曲不同？
  │ 3. 播放（音量60）                      │    ├─ 是：静默加载
  │ 4. 发送SEI                             │    │   （音量0播放）
  │                                        │    └─ 否：进度对齐
  │                                        │
[播放中]                                   │
  │                                        │
  ├─ 发送SEI（进度、isSinging=true）──────►├─ 同步进度显示
  │                                        │
  ├─ 到达切换点 ─────────────────────────►├─ 同时执行切换
  │   (两队都有时)                         │   （各自本地逻辑）
  │                                        │
  ▼                                        ▼
isSinging: true      ───────────►      isSinging: false
mute: false                           mute: true
音量: 60                              音量: 0
停止按钮: 显示                        停止按钮: 隐藏

[播放结束]
进度 >= 总时长
  │
  ├─ 发送SEI（isSinging=false）
  │
  └─ 所有用户收到后清空播放信息
```

## 十一、关键限制与边界条件

### 11.1 上麦限制

| 场景 | 结果 |
|------|------|
| 房间无流 | 允许，作为TeamA |
| 房间1队，对方未播放 | 允许，作为TeamB |
| 房间1队，对方正在播放 | **禁止**，提示"当前歌曲演唱完才能上麦" |
| 房间2队 | **禁止**，提示"房间已满" |

### 11.2 切换限制

- 仅当两队都在推流时才执行切换逻辑
- 单队播放时，切换逻辑不启用（避免观众进度停止）
- 切换只执行一次（通过 `hasSwitched` 标记）

### 11.3 SEI 发送限制

- 仅推流用户发送 SEI
- 播放状态变化时立即发送（不等待进度回调间隔）

### 11.4 播放器状态处理

- `.idle` 状态在加载新歌期间被忽略，不重置 UI
- 加载完成后根据实际播放状态更新 UI
